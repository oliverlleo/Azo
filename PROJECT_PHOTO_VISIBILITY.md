# Exclusão de fotos originais dos projetos
A biblioteca usa registros individuais na tabela existente `site_pages` (IDs `azo-project-photo-as-1`, etc.) com `items` JSON. A exclusão é lógica e reversível, não apaga o arquivo estático nem objetos do Storage. Desktop e miniatura são tratados como a mesma foto. Nenhuma política RLS ou permissão nova é necessária.
Antes de publicar, confirmar na instância AZO que `site_pages` aceita os IDs reservados e que visitantes têm SELECT, mas somente administradores ativos têm INSERT/UPDATE, inclusive para esses registros. Não afrouxar a RLS se houver erro. O painel verifica o administrador e relê o registro após gravar; a autorização definitiva é a RLS existente.
Teste manual: excluir a primeira foto de uma casa no painel; cancelar no modal e verificar que nada mudou; confirmar e abrir a página inicial, portfólio e página de serviço em uma janela anônima. Verificar nova capa, contagem da galeria, miniaturas e outra casa intacta. Excluir as seis fotos deve ocultar apenas aquela casa. Mostrar novamente deve restaurar a imagem. Testar tentativa de alteração com usuário não administrador, que deve falhar. A leitura de visibilidade com erro mantém projetos originais ocultos, evitando exibir uma foto removida por fallback.
Teste unitário: `node tests/test_project_photo_visibility.mjs`.

## Adicionar fotos
O botão Adicionar fotos permite selecionar um projeto original e enviar várias imagens através do Storage já usado pelo painel. Cada foto nova recebe um registro individual na mesma tabela protegida. Excluir uma foto adicional mantém o arquivo no Storage para permitir restauração. Testar upload autenticado e verificar se outro projeto não recebe as fotos; repetir com usuário não administrador e conferir que RLS e Storage rejeitam gravação. Acesso à instância de produção é necessário para validar essas políticas.
